= Command line

----
graalnix eval [--strict] [--json] [--raw] (-E EXPR | FILE) [-A ATTR] [--arg NAME EXPR] [--argstr NAME VALUE]
graalnix drv-path (-E EXPR | FILE) [-A ATTR] [--arg NAME EXPR] [--argstr NAME VALUE]
graalnix format [--width N] [--indent N] [--strict] [FILE...]
graalnix check [FILE...]
graalnix fix [--width N] [--indent N] [--strict] [FILE...]
----

`-h` or `--help` after any command prints its options.

== Commands

`eval`::
Evaluates the expression and prints the result in the same format as
`nix-instantiate --eval`.

`drv-path`::
Evaluates the expression to a derivation and prints its `drvPath`, like
`nix-instantiate`. When the derivation's `outputName` is not `out`, the path is
followed by `!<output>`.

`format`::
Formats the files in place, as nixfmt does.

`check`::
Prints the linter's findings, one per line as
`FILE:LINE:COLUMN: SEVERITY[RULE]: MESSAGE`, and changes no file.

`fix`::
Applies the linter's fixes to the files in place, then formats them.

== Input

`-E EXPR`, `--expr EXPR`::
Evaluates `EXPR`.

`FILE`::
Evaluates the file. A directory stands for its `default.nix`.

Give exactly one of the two.

`-A ATTR`, `--attr ATTR`::
Selects an attribute path in the result.

`--arg NAME EXPR`, `--argstr NAME VALUE`::
If the result is a function, calls it with `NAME` bound to the Nix expression
`EXPR`, or to the string `VALUE`.

== Output

These apply to `eval`.

`--strict`::
Forces the result deeply before printing it.

`--json`::
Prints the result as JSON.

`--raw`::
Prints a string result as is, without quotes or escapes.

== Evaluation

`-I PATH`::
Adds an entry to the search path for `<...>` lookups, such as
`-I nixpkgs=/path/to/nixpkgs`. The entries of `NIX_PATH` come after those given
with `-I`.

`--system SYS`::
Sets `builtins.currentSystem`.

`--show-trace`::
Prints the Nix call stack when the evaluation fails.

== Engine options

Any other option is handed to the GraalVM polyglot engine, as `--name` for
`name=true` or `--name=value`. This includes the language's own `--nix.*`
options and the Truffle tools:

`--inspect`::
Opens the Chrome DevTools debugger.

`--cpusampler`::
Profiles the evaluation.

Runtime compilation is off by default: on nixpkgs it made evaluations 4 to 10%
slower for 1.5 times the CPU and memory. Pass `--engine.Compilation=true` to turn
it back on.

== Files

These apply to `format`, `check` and `fix`.

`FILE...`::
The files to process. A directory stands for every `.nix` file below it.
Without any, the command reads standard input, and `format` and `fix` print
the result to standard output.

`--width N`::
Fits lines in `N` columns where possible, 100 by default.

`--indent N`::
Indents by `N` spaces, 2 by default.

`--strict`::
Makes the output depend less on how the input was laid out, like
`nixfmt --strict`.

`-q`, `--quiet`::
For `format` and `fix`, prints only errors, not the files rewritten and the
summary.

Files are read as UTF-8, and one that is not is refused. A file is written only
when its content changes. `format` and `fix` name each file they rewrite on
standard error, then a count of the files changed, unchanged and failed, and the time taken. A file that fails, such as one that does not parse,
is reported on standard error, and the other files are still processed.

`format` and `fix` follow the
https://treefmt.com/latest/reference/formatter-spec/[treefmt formatter spec]:

[source,toml]
----
[formatter.graalnix]
command = "graalnix"
options = ["fix"]
includes = ["*.nix"]
----

== Exit status

`0` on success and `2` on a usage error. `1` when the evaluation fails, when a
file cannot be read or does not parse, or when `check` finds an error or a
warning. Hints alone leave `check` at `0`.
