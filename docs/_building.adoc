= Building

The build uses https://jenesis.build[Jenesis], vendored in `build/jenesis`. Each
module's `module-info.java` declares its build, and the tool settings live in
`META-INF/build.jenesis/` next to the module's sources. The project-wide settings
live in `build.jenesis/`.

[source,sh]
----
nix develop
java build/jenesis/Make.java                                # compile, check formatting (palantir-java-format), run the tests and render these docs
java -Djenesis.format.rewrite=true build/jenesis/Make.java  # reformat the sources instead
java build/jenesis/Execute.java eval -E '1 + 1'             # run the launcher on the JVM
java -Djenesis.make.profiles=native build/jenesis/Make.java stage
                                                            # native launcher in target/stage/native/output
----

The command line comes in two modules. `cli` holds `format`, `check` and `fix`
and its own `graalnix` command with only these. `launcher` adds `eval` and
`drv-path`, which need the evaluator and so Truffle. `jenesis.properties` makes
`Execute.java` run the launcher; `-Djenesis.execute.module=cli/src/main/java`
runs the other. The native profile of `cli` is `native-lite`.

== Playground

The `web` module wraps the formatter and linter for JavaScript: `Playground`
exports `format`, `fix` and `lint`, each returning JSON. TeaVM compiles it with
its dependencies to `graalnix.js` at the module's package step, through the
project plugin in `plugins/teavm`, which `jenesis.plugins.properties` declares
and the module's `plugin-teavm.properties` switches on. TeaVM's jars are no
modules, so the plugin resolves them onto a class path and runs TeaVM in a JVM
of its own. Their pins live in the `web` declaration: TeaVM's asm is older than
the tools', so they cannot share the bill of materials.

TeaVM's class library has no `HexFormat` and no `String.lines`: code the
playground reaches must do without them, or the build fails naming the method.

[source,sh]
----
java build/jenesis/Make.java build/modules/compose/module/package-module-web+src+main+java
nix shell nixpkgs#nodejs -c node web/check.cjs \
  target/build/modules/compose/module/package-module-web+src+main+java/custom/teavm/delegate/teavm/output/javascript/graalnix.js \
  format/src/test/java lint/src/test/java/cases   # the formatter and linter test cases, in JavaScript
----

== Documentation

This documentation is written in AsciiDoc in `docs/`. Files whose names start
with `_` are only included. The Jenesis Asciidoctor plugin, switched on by
`build.jenesis/asciidoctor.properties`, renders it during the build. Run `stage`
to get the HTML in `target/stage/project/output/docs/`, or build it with Nix:

[source,sh]
----
nix build .#docs
----

== Dependencies

Dependency versions and checksums live in one bill of materials,
`build.jenesis/pin-graalnix.properties`, which every module imports with
`@jenesis.bom`. After changing a dependency, regenerate it:

[source,sh]
----
java build/jenesis/Make.java pin
----

`jenesis.properties` points `pin` at that file and names the groups it holds:
the dependencies, and the tools the modules run (palantir-java-format, JaCoCo),
which the modules import it into as `@jenesis.bom palantir:tool/pin-graalnix.properties`.
A plugin's own version stays pinned in each declaration, as
`palantir/module/...`: Jenesis does not read it from a file. The project
plugins' tools are pinned in `jenesis.plugins.pin.properties`.

== Nix

`nix/package.nix` builds offline. `nix/pins.nix` reads the pins of the module
declarations and of both pin files, and fetches each pinned jar and POM, so a
new pin needs nothing more.

The flake provides:

`graalnix`:: the launcher on OpenJDK 25. It runs the bundle the launcher's
`packaging.properties` asks for: its jars and the `java` argument file that
names them. Without GraalVM's compiler, Truffle runs its fallback runtime,
which only interprets; runtime compilation is off by default anyway.
`graalnix-native`:: the launcher as a static native image, built with GraalVM.
`graalnix-lite`:: the `cli` module on OpenJDK 25: `format`, `check` and `fix`
only, without Truffle.
`graalnix-lite-native`:: the `cli` module as a static native image.
`playground`:: `web/playground/index.html` and `graalnix.js`: a page that
formats, fixes and lints Nix in the browser, opened as a file, with no server.
`docs`:: this documentation, rendered to HTML.
`tests`:: a check that runs the test suite on the JVM and outputs its JaCoCo
report.
`playground-tests`:: a check that runs the formatter and linter test cases
against `graalnix.js` in Node.js.
