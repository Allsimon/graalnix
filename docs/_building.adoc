= Building

The build uses https://jenesis.build[Jenesis], vendored in `build/jenesis`. Each
module's `module-info.java` declares its build, and the tool settings live in
`META-INF/build.jenesis/` next to the module's sources. The project-wide settings
live in `build.jenesis/`.

[source,sh]
----
nix develop
java build/jenesis/Make.java                                # compile, check formatting (palantir-java-format), run the tests and render these docs
java -Djenesis.format.rewrite=true build/jenesis/Make.java  # reformat the sources instead
java build/jenesis/Execute.java eval -E '1 + 1'             # run the launcher on the JVM
java -Djenesis.make.profiles=native build/jenesis/Make.java stage
                                                            # native launcher in target/stage/native/output
----

== Documentation

This documentation is written in AsciiDoc in `docs/`. Files whose names start
with `_` are only included. The Jenesis Asciidoctor plugin, switched on by
`build.jenesis/asciidoctor.properties`, renders it during the build. Run `stage`
to get the HTML in `target/stage/project/output/docs/`, or build it with Nix:

[source,sh]
----
nix build .#docs
----

== Dependencies

Dependency versions and checksums live in one bill of materials,
`build.jenesis/pin-graalnix.properties`, which every module imports with
`@jenesis.bom`. After changing a dependency, regenerate it:

[source,sh]
----
java build/jenesis/Make.java pin
----

`jenesis.properties` points `pin` at that file and names the groups it holds:
the dependencies, and the tools the modules run (palantir-java-format, JaCoCo),
which the modules import it into as `@jenesis.bom palantir:tool/pin-graalnix.properties`.
A plugin's own version stays pinned in each declaration, as
`palantir/module/...`: Jenesis does not read it from a file. The project
plugins' tools are pinned in `jenesis.plugins.pin.properties`.

== Nix

`nix/package.nix` builds offline. `nix/pins.nix` reads the pins of the module
declarations and of both pin files, and fetches each pinned jar and POM, so a
new pin needs nothing more.

The flake provides `graalnix` (the native binary), `docs`, and a `tests` check
that runs the test suite on the JVM and outputs its JaCoCo report.
